Your first rule

A workflow is a rule: when something happens, do something about it. You build it by picking from lists, with no code.

1. Pick what starts it

Open Workflows and choose New workflow. First, pick what starts a run:

A client sends a messagea reading, an alert, a button pressA client connects or disconnectswhen something goes quietOn a scheduleevery morning at 7, every hourBy handa button in the console

A workflow can also start when another service calls its own URL. All five triggers are in the node reference.

2. Add a check

Add an If step to decide when to act, like when temp is below 2. Runs that don't pass the check stop quietly.

When greenhouse-sensor reads below 2 °C send a Telegram message

3. Say what happens

Add one or more steps after the check. Send to client switches something on your board, and Telegram, Discord or Email send you a message.

Messages go through an account you add once under Integrations, such as your own Telegram bot. Use Test there to check it works before you rely on it.

4. Publish and test

Choose Publish. The Problems list shows anything that's missing, and takes you to the step that needs it.

Every run shows up in the workflow's Runs tab, with the path it took and where it stopped if something went wrong.

TipWant to try it without waiting for frost? Add a second workflow that starts By hand and sends you the same message.
