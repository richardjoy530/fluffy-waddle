A. Persistent sockets

The connection never drops. On purpose.

Every client — an edge device, a backend, a browser — holds one always-open WebSocket. Commands travel down it in 12ms median; telemetry travels up. Reconnects, backoff and message resumption are the SDK's problem, not yours.

B. Stateful workflows

Runs with memory.

A run isn't a function invocation — it's a durable object. It waits on delays and events without burning compute, checkpoints every step, and resumes exactly where it stopped after any restart. Every branch and ack is in the audit trail, replayable.

C. Sandboxed marketplace

Integrations that can't overreach.

Third-party services mount as virtual clients — same protocol as your hardware, none of the trust. Each one runs in a sandbox with explicit channel permissions you grant and revoke per workspace.
