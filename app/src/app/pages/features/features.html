Persistent connections

The connection stays open, by design.

Every client — an edge device, a backend service, a browser — holds one always-open connection. Readings travel up it the moment they are taken, and commands travel back down without waiting for the next poll. Reconnects, backoff and picking up missed messages are the SDK's job, not yours.

Stateful workflows

Runs that keep their place.

A run is not a function call that has to finish before it is forgotten. It waits on delays and events without consuming compute, saves its progress at every step, and resumes from exactly where it stopped after a restart. Every branch and acknowledgement is kept, so any run can be replayed.

Sandboxed integrations

Integrations that can't overreach.

Outside services connect as virtual clients — the same protocol your hardware speaks, without the same trust. Each one runs in a sandbox limited to the channels you grant it, and you can revoke that access per workspace at any time.
